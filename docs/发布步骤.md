# 把这个项目发布到 GitHub · 新手步骤

> 你不需要会 Git 命令也能发布。**推荐用 GitHub Desktop（全程点鼠标）**，下面两条路都写了，选一条走就行。
> 发布前请确认：`dist\` 里的 exe **不要**上传到代码仓库，后面第 5 步会教你怎么单独发布它。

---

## 第 0 步：准备

| 需要 | 说明 |
|---|---|
| GitHub 账号 | 去 <https://github.com/signup> 注册，免费。用户名会出现在仓库链接里，想好再定 |
| GitHub Desktop（推荐） | <https://desktop.github.com/> 下载安装，装完用浏览器登录同一个账号 |
| 或者 Git for Windows（命令行路线） | <https://git-scm.com/download/win>，安装时一路默认即可 |

---

## 第 1 步：在网页上建一个空仓库

1. 打开 <https://github.com>，右上角 **+** → **New repository**。
2. **Repository name**：建议 `fnf-mod-launcher`（全小写、用 `-` 连接，别用中文和空格）。
3. **Description**：`FNF 模组启动器 — 自动扫描模组、识别引擎、曲目试听与存档备份`。
4. **Public / Private**：想给别人看就选 **Public**；Private 也能用，只是别人看不到。
5. **三个勾选框全部不要勾**（README / .gitignore / license 我们已经准备好了，勾了会冲突）。
6. 点 **Create repository**。新页面会给你一条 `https://github.com/你的用户名/fnf-mod-launcher.git` 这样的地址，先复制留着。

---

## 第 2 步（路线 A，推荐）：用 GitHub Desktop 上传

1. 打开 GitHub Desktop → 登录 → 菜单 **File → Add local repository…**
2. 选择文件夹：`D:\fnf\github\FNF-Mod-Launcher`
   - 如果它提示 "not a Git repository"，点 **create a repository**，然后：
     - Name 保持 `FNF-Mod-Launcher`
     - Local path 选 `D:\fnf\github`
     - **不要**勾 "Initialize with README"（我们已经有 README 了）
3. 左侧会列出所有改动。检查一下列表里**没有** `launcher.ini`、`启动日志.txt`、`dist\` 这些东西（`.gitignore` 已经帮你挡住了）。
4. 左下角 **Summary** 填 `feat: FNF 模组启动器 v1.9 初始提交`，点 **Commit to main**。
5. 顶部点 **Publish repository**：
   - Name 填 `fnf-mod-launcher`
   - **取消勾选 "Keep this code private"**（想要公开的话）
   - 点 **Publish repository**

完成。打开 `https://github.com/你的用户名/fnf-mod-launcher` 就能看到项目了，首页会直接渲染 README 和截图。

---

## 第 2 步（路线 B）：用命令行上传

打开 PowerShell（开始菜单搜 PowerShell），**逐条**复制粘贴执行：

```powershell
# 1) 进入仓库目录
cd D:\fnf\github\FNF-Mod-Launcher

# 2) 第一次用 Git 的话，先告诉它你是谁（换成你的 GitHub 邮箱和昵称）
git config --global user.name "你的昵称"
git config --global user.email "你的邮箱@example.com"

# 3) 初始化仓库并提交
git init
git add .
git commit -m "feat: FNF 模组启动器 v1.9 初始提交"

# 4) 关联到刚才建的远程仓库（地址换成你自己的）
git remote add origin https://github.com/你的用户名/fnf-mod-launcher.git
git branch -M main
git push -u origin main
```

> 第一次 `git push` 会弹出一个浏览器登录窗口，登录后即可。
> 如果提示要输密码：**不要输 GitHub 密码**，去 <https://github.com/settings/tokens> 生成一个 Personal Access Token（勾选 `repo`）当密码用；或者改用 GitHub Desktop。

---

## 第 3 步：检查发布结果

在仓库页面确认这几件事：

- [ ] README 显示了标题、截图（`docs/main.png`）和功能列表
- [ ] 文件列表里有 `LICENSE`、`.gitignore`、`build.ps1`、`src/`、`docs/`
- [ ] **没有** `dist/`、`launcher.ini`、`启动日志.txt`、`backups/`
- [ ] 右侧栏能看到 **MIT license**（因为 LICENSE 文件被识别了）

---

## 第 4 步：让别人能下载 exe（Release）

exe 不要放进代码仓库（每次构建几百 KB 二进制，历史会越来越大）。用 **Releases**：

1. 仓库页面右侧 **Releases** → **Create a new release**
2. **Choose a tag**：输入 `v1.9` → 点 "Create new tag: v1.9 on publish"
3. **Release title**：`FNF 模组启动器 v1.9`
4. **Describe this release**：简单写两句更新内容，例如
   ```
   首个公开版本。
   - 自动扫描模组、识别引擎与版本
   - 曲目试听、截图预览、存档备份
   - 拖入文件夹 / zip / rar / 7z 即可安装
   ```
5. **Attach binaries**：把这个文件拖进去 → `D:\fnf\github\FNF-Mod-Launcher\dist\FNF启动器.exe`
6. 点 **Publish release**

之后 README 里的 `[Releases](../../releases)` 链接会自动指到你最新的版本页。

---

## 第 5 步：以后改了代码怎么更新

**GitHub Desktop**：改动保存 → 打开 Desktop → 写 Summary → Commit → 右上角 **Push origin**。

**命令行**：

```powershell
cd D:\fnf\github\FNF-Mod-Launcher
git add .
git commit -m "fix: 修了什么"
git push
```

如果出了新版本要重新发 exe：**Releases → Draft a new release → 新 tag（如 v1.9.1）→ 上传新 exe → Publish**。
不要覆盖旧 tag，那样别人已经下载的版本会和 tag 对不上。

## 必须注意的 8 条

1. **别把本地数据传上去**
   `launcher.ini` 里有你电脑上的目录（`root=D:\fnf\fnf`）、模组名和启动统计；`启动日志.txt`、`backups\`、`缺失模组.txt` 也是本机数据。
   `.gitignore` 已经排除了它们，但**提交前一定看一眼 GitHub Desktop 左侧列表**，别手滑勾上。

2. **exe 走 Release，不进仓库**
   仓库里只放源码。想给别人直接用的版本，放 Releases 附件。

3. **仓库名用英文**
   `fnf-mod-launcher` 这种。中文名能用，但链接会变成一长串 `%E5%90%AF...`，别人念不出来也不好搜。

4. **公开仓库 = 全世界都能看**
   提交前想清楚：代码里有没有你不想公开的东西。目前 `src/Dialogs.cs` 里写着 `作者：蘑菇汉化组组长` 和一个 B 站主页链接，**保留还是删掉，你自己定**。

5. **别传游戏本体和模组文件**
   仓库只放启动器代码。游戏、模组、素材体积大且有版权问题，一律不传。

6. **站点图标是第三方商标**
   `assets/siteicons/` 里的 GameJolt / GameBanana / KBH logo 版权属于对方。README 里已经注明"仅用于指代下载来源"，个人项目一般没问题；如果以后要商用，换成自制图标。

7. **中文乱码只会在"别人改代码"时出现**
   源码是 UTF-8 无 BOM，`build.ps1` 里带了 `/codepage:65001`。别人如果用记事本/老编辑器改成 GBK 保存，中文会变乱码——`.gitattributes` + `.editorconfig` 已经尽量防护，但提醒一句更保险。

8. **第一次 push 失败多半是两件事**
   - `fatal: not a git repository` → 没在正确目录执行 `git init`，先 `cd` 到 `D:\fnf\github\FNF-Mod-Launcher`。
   - `rejected ... fetch first` → 远程仓库里已经有内容（比如建仓库时勾了 README）。解决：`git pull --rebase origin main` 再 `git push`。
